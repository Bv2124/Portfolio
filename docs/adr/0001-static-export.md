# 1. Ship the site as a static export

- **Status:** Accepted
- **Date:** 2026-09

## Context

The site is a personal portfolio: a home page plus a handful of case-study pages. All content
changes when the author edits it, never per request. It is hosted on Vercel and has to be fast on
phones, crawlable, and cheap to run.

## Decision

Use Next.js App Router with `output: 'export'` and `trailingSlash: true`. Every page, the sitemap
and robots.txt are generated at build time into `out/` and served from the CDN. Case-study routes
use `generateStaticParams` with `dynamicParams = false`, so an unknown slug is a 404.

## Consequences

- No server, no cold starts, no runtime to patch. Most Next.js advisories (Server Actions, image
  optimisation, middleware) don't apply.
- Anything "live" must be computed at build time or in a small client component. Years of
  experience and job durations render a build-time value and correct it after load
  (`components/ui/Live.tsx`), so the HTML is never wrong by more than the time since the last deploy.
- `next/image` optimisation and request-time features aren't available. There are no raster images
  except the social preview, which is generated by `scripts/og-image.mjs` and committed.
- Metadata routes must be marked `export const dynamic = 'force-static'`, and canonical/sitemap URLs
  must carry the trailing slash the export serves.
- Pages are tested exactly as deployed: Playwright and Lighthouse CI run against `out/`.
